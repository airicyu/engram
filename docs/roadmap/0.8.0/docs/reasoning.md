# 0.8.0 WHY

進行中的月份與年份若也常改，鏈上會有三層半成品，Ask 無法分辨哪一層才是定稿。週是使用者在「現在」還用得上的最短回顧，所以只開放這一層。

標記放 frontmatter `open: true`，而不是只靠正文「本週至今」：正文句子會被改寫，程式無從穩定判斷半成品。收成時刪掉鍵，Ask 才不會把短稿講成定論。不另開 `*.draft.md`，避免同一週兩份檔、連結與 UI 要選讀哪一份。

缺日不進釐清題。沒被 capture 的日子沒有事實可問；出題只會逼模型編「那天有沒有事」。清單放在 job `output`，因為它是這一次蒸餾的機械結果，不是記憶。掃全庫找歷史空洞會把舊的空白日全部冒出來，所以只切本批最早與最晚日期之間。

使用者中途點名「寫這週」若改成檔尾 append，短稿會變成合訂本。整份取代沿用 chain 既有寫法。週還沒結束就清掉 `open`，等於把未完成週說成定稿，所以點名只取代正文、標記留到週日之後。

跨月的進行中週稿不能當已結束月記的上層來源：短稿含下個月的日子，也還沒取捨。那些日子改讀 day。年記只經月記，不必再濾一層。

缺日區間只認池裡可解析的 `ts`。池空而 clarify 仍跑，沒有可掃的事件日，成功時寫空陣列，而不是改去讀 clarify。清單是這次 job 的結果，失敗就不寫。
