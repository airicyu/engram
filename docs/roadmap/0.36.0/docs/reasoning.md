# 0.36.0 reasoning

做什麼以 [INDEX](../INDEX.md) 為準。本檔只留動機與反例。

## 為何記憶鏈／圖不進 0.36、也不先排下一版

- 左欄四項在殼完成當日就必須可點；搜索內頁不改，沒有獨立版本的工作量。
- 事件與釐清都是「當下與系統說話」；記憶鏈／圖是另一套視覺，0.36 出貨後再看現有列表夠不夠。
- 一個 version 一次 shipped。Track 1→2→3 是實作序，不是三個出貨號。

## 否決

| 方案 | 為何不選 |
|------|----------|
| 三版：殼／搜索＋郵箱／記憶 | 搜索幾乎是搬家；中間那版空洞 |
| 0.36 只出殼、事件仍舊畫面 | 左欄「事件」名實不符；STM `entries[]` 已在 0.35 等這頁 |
| 改 hash 把 consolidate 廢成 query | 破壞 0.31 深鏈；本版用「事件＋內 tab」對應 `#/consolidate` 即可 |
| 釐清改 API 成 thread 資源 | 產品只要隱喻；檔案／端點已夠用 |

## 失敗模式

- **不要**為左欄發明新 SceneId（如 `events`）而丟 `activities`／`consolidate`。
- **不要**在 0.36 順手改 Memory 列表或 Seek Ask。
- **不要**把 aside 寫進 activities。
