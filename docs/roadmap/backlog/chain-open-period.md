# 進行中的週記，以及日記空洞

**狀態：** 構想。尚未排進版本。

## 題意

升層閘門規定：week／month／year 只在該時段已結束，或使用者這次明說要寫時才動。結果是「現在」在鏈上幾乎看不見——進行中的月份沒有月記，當週若還沒過週日就沒有週記，中間缺的日記也不會被補，只會在之後的釐清題裡被問「那幾天有沒有事」。空洞問不出來；沒被 capture 的日子，系統不該假裝能用出題填上。

要做成：

- 進行中的週允許一份短稿，檔名與正式週記相同，正文標成「本週至今」（第一行仍是 `##` 題材，不是週號目錄）。時段結束後的下一次 distill 把它收成正式週記：取捨、刪掉過程旁白，不再保留「至今」標記。
- 進行中的月、年仍不寫，除非使用者這次明說。不要把「至今」擴散成三層都常改。
- Distill 若發現本批涵蓋的日曆區間裡有整日沒有 day 檔，在 job 結果或 day 不寫的前提下留一個**機械清單**（缺哪些 `YYYY-MM-DD`）。不要為這些空洞新建釐清題。補記仍走事件 capture，再由下一次 distill 寫 day。

## 可能要定（排進版本時寫進 INDEX）

- 「本週至今」的標記放 frontmatter（例如 `open: true`）還是正文約定。收成正式稿時必須清掉，避免 Ask 把半成品當定稿。
- 缺日清單放哪：job JSON（不進 vault）為宜。不要在 `memories/` 另開一本缺口帳。
- 使用者中途明說「寫這週／這個月」時，與自動「至今」稿如何疊加：仍是整份取代，不是檔尾 append。

## 不要當成題目的一部分

- 用釐清題詢問「某日有沒有值得記的事」
- 進行中就寫月記、年記
- 把七篇日文串成週記（正式收成仍要取捨）
- Server 判斷「這天重不重要」
